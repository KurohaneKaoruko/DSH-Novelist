# 大纲、细纲与节奏设计

细纲是“章节介绍驱动扩写”工作流的核心：你按细纲逐项落实成文（写法见《novel-prose-standards》的生成时干预），细纲质量直接决定章节质量。大纲回答“这一卷讲什么”，细纲回答“这一章每一拍干什么”。

## 一、总纲与卷纲

- 总纲包含：核心设定（一句话）、金手指与代价、主线冲突、分卷规划（每卷的目标/对手/高潮/卷末钩子）、主要人物弧光。
- 卷纲包含：本卷目标、开卷局面、关键事件序列（按“压→转→爽→钩”组织）、新出场人物/新地图、卷末大高潮与跨卷钩子。
- 大纲先行但允许滚动修订：每卷末回头校准一次总纲；修订后的总纲才是后续细纲的依据。

## 二、黄金三章（开篇生死线）

- 前 300 字交代主角身份处境并抛出异常/危机/金手指；前 1000 字内出现第一次冲突、爽点或强悬念；三章内完成“身份确立→异常危机→金手指→第一次反击/期待建立”。
- 开篇量化指标（番茄系平台实测有效）：开篇章节**每 400 字一个爽点**；**对话占比 60% 以上**，口语化接地气；优先**纯对话/动作开局**，忌环境铺陈开局；每章 2000–2500 字；章尾强钩子。
- 禁忌：大段设定灌输、路人视角开场、慢热铺垫、出场人物过多、开局写日常。
- 第一章结尾必须建立“追读理由”：具体的期待，不是抽象的伏笔。

## 三、爽点公式

- 每章至少一个情绪点：打脸、升级、收获、反转、暧昧、危机解除等。
- 爽点公式：**压（铺垫憋屈）→ 转（契机）→ 爽（释放）→ 钩（新期待）**。压要压够但不过夜（一章内闭环的爽点不留到下一章）；释放要具体可感（数字、对比、旁人反应），不写“他变强了”。
- 期待感管理：每个爽点释放的同时埋下一个更大的期待（新对手、新地图、新谜团）。

## 四、毒点防火墙（读者雷区，构思与扩写全程规避）

- 人设雷：绿帽/NTR、圣母（无底线善良救敌）、降智（为推剧情做不合理行为）、主角被动（系统代打、傀儡主角）、无意义的隐忍憋屈。
- 剧情雷：关键冲突靠巧合解决、反派无脑送人头、金手指无限加码无代价、重要配角无故消失。
- 价值观雷：美化犯罪、无端虐主、歧视性内容。
- 脑洞产出与章纲生成时逐条自检；正文阶段 lint 类检查不含这些，需人工/模型按此清单核对。

## 五、节奏量化参考

- **单章 2000–4000 字是硬默认**（用户未特别说明时必须遵守）：不写 1000 字的碎片章，也不单章破 5000 字；体量超出时按场景拆到下一章。
- 每章至少一个情绪点；连续 3 章无爽点即为拖沓，必须插入事件。
- **收尾纪律**：结尾必须收在场景或节拍的落点上（事件收束/转折抛出/情绪余韵），禁止中途截断、禁止半场戏机械切断——写到一半的场景要么在本章写完，要么明确留到下一章开场续写。
- 每 3–5 章一个小高潮，每卷末一个大高潮并留跨卷钩子。
- **事件-章节奏单元**：一个完整事件（冲突萌芽→升级→高潮→收尾）用 3–5 章展开，每章推进一拍；不要一章塞完一个事件（赶），也不要一个事件拖过 6 章（注水）。
- 长短章交替、张弛有度；大高潮后安排 1–2 章缓冲（日常/感情/收获）再开新冲突。
- 中段用支线、升级与新地图调节奏，防止主线疲劳。

## 六、钩子类型库（章末留钩）

八种章尾钩，在情绪/动作的**前一秒**断章（绝不在情绪最高点写完）：
1. 悬念钩：新信息抛出一半（信物来历、幕后黑手的一角）。
2. 危机钩：危险逼近但本章不解（敌人在路上、倒计时开始）。
3. 期待钩：明确的下一章看点（明天就是比武、即将见面）。
4. 情绪钩：情绪余韵（和解未说出口、误会刚埋下）。
5. 反转钩：最后一句话推翻本章认知。
6. 打脸预告钩：下一章即将碾压（配合打脸四拍的“沉默”拍断章）。
7. 关系钩：人物关系即将变化（摊牌、重逢、背叛前夜）。
8. 信息钩：关键信息即将揭晓（信封拆开前一秒）。

钩子靠事件与具体信息，不靠感叹与抒情；埋的钩 1–3 章内必兑现，大钩套小钩（卷级主悬念下挂章级小悬念）。

七种开篇结构（新书/新卷开篇从其中选 2–3 种各写一版再定）：悬置危机 / 身份反差 / 结局倒挂 / 替身挡刀 / 金手指激活 / 日常爆破 / 反派开局。每版给：3 句以内的开篇文字 + 钩点解析（读者为什么必须往下看）+ 承接建议（怎么接黄金三章）。

## 六、标准细纲模板

每章细纲用以下结构（`novel_chapter_plan` 类任务按此组织；细纲定稿后由你亲自按其成文）：

```
第 N 章细纲：《章节标题》
- 本章目标：这一章在主线上推进什么（一句话）
- 承接：上一章结尾的场景/情绪，本章如何接
- 事件序列：3–6 拍，每拍一句话（谁做了什么、结果如何）
- 转折点：本章最关键的一拍（位置约在章节 60–75% 处）
- 爽点：类型 + 压转爽的分布
- 伏笔操作：铺设哪条 / 发酵哪条 / 回收哪条（对应伏笔清单编号或名称）
- 出场人物：名单 + 每人本章的状态与动机要点
- 结尾钩子：类型 + 具体内容
- 预计字数：
```

**本章监控表**（细纲附表，成稿后逐项对照验收）：

```
| 拍 | 情绪 | 爽点/钩 | 伏笔 | 验收 |
|----|------|--------|------|------|
| 1  | 压（低） | —     | 发酵#3 | ☐ |
| 2  | 升      | 微爽   | —     | ☐ |
| 3  | 峰      | 主爽点 | —     | ☐ |
| 4  | 落+钩   | 钩子   | 铺设#7 | ☐ |
```

情绪列填曲线走向（压/升/峰/落），爽点列标类型与位置，验收列成稿后勾选——任何一拍“写了但没落实”就是本章欠账，下一章必须补。

## 七、情节推演方法

- 面对剧情困境（卡文、转折无力）时，生成多个差异化方案，按“收益/风险/与前文契合度”三轴评估，不要接受第一个方案。
- 推演“如果……会怎样”：一个强情境（金手指+限制+对手）胜过一堆散点情节。
- 反派动机自洽检查：反派的每一步都应是他立场上的最优解；降智推进剧情是硬伤。

## 八、拆书方法

拆解爆款时关注四个层面（流程详见《novel-analysis》）：
1. 结构层：开篇钩子怎么设、爽点周期多长、每章钩子类型。
2. 节奏层：压爽比、章节字数分布、高潮间隔。
3. 人物层：主角欲望与恐惧、配角功能定位、反派逻辑。
4. 文风层：叙述距离、对话密度、描写习惯（可回流给文风卡——按《novel-project》的文风卡格式更新）。
拆书产出的是“可复用的结构”，不是情节本身。

## 任务流程

**灵感生成（脑洞）**：批量生成差异化创意（默认 8-10 个），每个按**脑洞公式**组织：`题材 + 创意（独特金手指 / 反差人设 / 有趣世界观设定）+ 具体高光剧情预埋`。高光预埋是给读者“名场面”的预期（如“操场雨中舞剑开天门”），比抽象设定更有追读驱动力。创意之间题材、视角、爽点类型拉开差距；每个过一遍毒点防火墙（第五节）。

**大纲整理**：把零散素材组织成结构化大纲。结构选择：三幕式 / 起承转合 / 卷-章结构（默认）/ 主线+支线 / 自由结构。先提炼核心设定与主线冲突，再分层展开；保留用户原始想法的关键词，不擅自替换方向。输出 Markdown 大纲。

**大纲优化**：按节奏量化标准诊断现有大纲（拖沓段、连续无爽点、钩子缺失、支线喧宾夺主、高潮间隔过长）→ 给出调整方案（每条：问题 → 改法）→ 输出优化后完整大纲。保留既定主线与结局方向，除非用户要求推翻。

**大纲续写（百章框架法）**：先产出“一句话总控”——用一句话高度概括后续剧情的核心走向与核心冲突；把总控代入，每轮生成后续 10 章的详细章纲，同一总控可连续展开多轮（百章框架一次成型）。要求与前文因果连贯、伏笔清单待回收项择机安排、新冲突强度不低于已有最高点。用户确认总控后再批量展开，避免方向性返工。

**章节规划**：把剧情弧线拆解为逐章计划，每章按标准细纲模板（见第六节）填全字段，附本章监控表。

**情节推演**：面对剧情前提或卡文困境，生成多个差异化方案（默认 5 个）。每案含：一句话走向、关键转折点、情绪与爽点收益、风险与代价。角度可选：多种可能走向 / 反转设计 / 危机破局 / 人物两难 / 伏笔设计 / 爽点强化。按“收益/风险/与前文契合度”评估，不推荐第一个想出来的。

**书名与简介包装**：书名——题材关键词 + 爽点暗示 + 检索友好；给 5-8 个候选分组（直白型/悬念型/反差型），各配思路。简介——前两行抛冲突与金手指，中段给爽点预期，结尾留钩；150-300 字；注意平台风格差异。前情提要（200 字内，只讲读后文必需的信息）与章末摘要（100 字内，本章事件与钩子）同此节。
